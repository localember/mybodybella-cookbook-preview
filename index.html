    How this would work on the live site

    This section is for us, not for the client. It is a design preview of one cookbook recipe page. The recipes and the cookbook itself are labeled placeholders.

    Access: locked to buyers of that cookbook

    Her members-only system is already in the custom Body Bella Recipes plugin (body-bella-recipes), and it is currently off. On mybodybella.com/my-recipes/, the Who has access tab lets Rimsha add emails, set how many weeks someone has access, and later click Switch on private access. Clients then enter their email and get a sign-in link. Until that switch is on, the recipe library is open to anyone who has the link.

    That system is built for the whole recipe library, not for one cookbook at a time, and it is not tied to a purchase. I did not find a third-party membership or shop plugin in the public WordPress REST API. The public API namespaces are Breakdance, LeadConnector, Rank Math, Google Site Kit, and a Local Ember API. There are no WooCommerce, MemberPress, Paid Memberships Pro, Wishlist Member, or Restrict Content routes. There is also no /shop/, /store/, /books/, or /cookbooks/ page, and no product post type in the public API.

    A simple approach for the live build:

    1. Give each cookbook its own page, for example /cookbook/sample-cookbook/.
    2. Lock that page to people who bought that cookbook. Extend the existing email-link access so a person can be granted a specific cookbook, not only the whole library. After purchase, their email is added to that cookbook's access list. They log in with the same email-link pattern already built.
    3. Someone who has not bought it sees a teaser: the cover, title, short intro, and a buy button. They do not see the recipes.

    Assumptions to flag. Cookbooks may be sold off the website today, or the purchase flow may not exist yet. I could not verify a shop or checkout on mybodybella.com. If they later sell cookbooks through WooCommerce (or another shop), checkout can grant the cookbook access automatically. Until then, Rimsha could add a buyer to that cookbook's access list by hand, the same way she would add someone to the recipe library list. I also could not re-download the live recipe-library HTML in this pass (the host served a bot challenge to some requests), so the plugin identification is from our Body Bella Recipes copy and from the live REST API namespaces, not from a fresh view of every plugin path in the page source.

    How Rimsha adds recipes

    She keeps using the same flow she uses now. Nothing moves into WordPress admin.

    1. Go to mybodybella.com/my-recipes/ and enter the passphrase if this device has not already been remembered.
    2. Paste the recipe (and an optional photo), click Check this recipe, then Add it to my website.
    3. Tag the recipe with the cookbook. The clean way is a new Cookbook taxonomy on the existing bb_recipe post type, with one term per cookbook. The cookbook page then shows only recipes with that term. Food categories (Chicken, Salads, and the rest) stay automatic from the name and ingredients, as they do today.

    The current add and edit screen does not have a cookbook field. We would add a cookbook picker on add and on edit, similar to the existing Also findable as box on Edit. Rimsha chooses the cookbook when she pastes or when she edits. To launch another cookbook later, we add a new taxonomy term and a new restricted page. The page template stays the same.

    Assumptions to flag. This is based on the Body Bella Recipes plugin as we last had it, including the /my-recipes/ paste screen and the bb_recipe post type. I could not independently re-open /my-recipes/ in this pass. If the plugin has changed since then, the picker should still be added to whatever screen Rimsha uses now, not a new wp-admin workflow.

    What this preview is using

    This page is driven by one data file, data/sample-cookbook.json. Copy that file, change the title, intro, cover, and recipes, and open the preview with ?book=your-slug to mock the next cookbook. The search box, category chips, and cards stay the same.
